## 4. 根因（按影响排序，均有 session 证据）

1. **生效 maxSteps=18 ≠ patch 配置 50**。14/20 会话出现 `Step Budget 耗尽（18）`：
   模型在 18 步内未走完 13 工具链（含重试与内置 read/write 步骤），后续 `penx1_generate_report`
   被 `INVALID_PHASE` 拦截，模型转而用内置 `write` 手写报告。
   `cordis.patch.dev.yml` 与 `cordis.patch.yml` 均为 `maxSteps: 50`，但 08-19 headless 快照
   （`artifacts/runtime/cordis-headless.snapshot.txt` L442）即显示 `maxSteps: 18`，
   08-24 实际运行同样为 18 → **配置解析/合并优先级问题（profile 内置插件配置覆盖了 patch 插入值），待溯源修复**。
2. **Guard 不约束内置工具**（workflow-guard.ts `apply()`）：无 runId 的非 penx1 工具
   （write/read/bash/str_replace_editor/todo_write）直接 `next()` 放行，
   模型可绕过 evidence guard 与报告 Gate 手动落盘报告（14/20 实际发生）。
3. **Gate 值漂移**：模型对 mfg/listing 偏宽（CG 附条件而非 NO_GO）。schema enum 允许三 Gate 均 CG；
   KB DOC-X2（缺实测不得写入 Listing）未被强制为硬约束，仅 baseline-1 给出期望的 CG/NO_GO/NO_GO。
4. **产品身份污染**：harness 仓库根目录存在旧版 PEN-X1 报告（手写笔/TPMS 内容，如
   `PEN-X1-ANALYSIS-REPORT.md` 手写×8、`PEN-X1-北美Amazon产品机会分析报告.md` 手写×5），
   模型经 `read` 工具读入并带入新报告（12/20）。数据边界（仅 KB + Mock）目前只约束数据源插件，
   未约束内置文件工具。
5. **API 计划级配额**：新 key 返回 `429 token plan limit exhausted`（quota_exceeded_error，
   连 5-token ping 均 429，属计划级耗尽而非 RPM/TPM 分钟级）；旧 key 正常。4 个失败 case 均为
   配额原因，换 key 后 4/4 通过，与业务代码无关。
